# 시그널 데일리 에디토리얼 가이드

> 제품 표기: 이 저장소와 사이트는 제품을 **Signal Daily**(한국어 문장에서는 "시그널 데일리")로 표기한다.
> **Signal Room**은 이전 표기(alias)이며, 코드·문서·사이트 문구에는 이제 Signal Daily를 쓴다.
> 이 문서는 `/standards`(공개 편집 원칙)와 [docs/pipeline.md](pipeline.md)(파이프라인)를 매일의 편집
> 작업 수준으로 구체화한다. 충돌 시 공개 원칙과 `src/content.config.ts`·`scripts/validate.ts`의
> 스키마·게이트가 우선한다. 스키마·코드 변경 없이 적용 가능한 규칙만 담는다.

## 1. 목적과 적용 범위

- **주 독자**: 의사결정에 인텔리전스를 참고하는 테크·비즈니스 전문가.
- 목적: 매일 4버티컬 에디션의 선별·작성·리뷰 기준을 고정해, 발행되는 모든 아이템이 같은 품질
  기준을 통과하게 한다.
- 적용 범위: `src/content/editions/<date>/<vertical>.json`으로 발행되는 데일리 에디션의 편집 규칙.
- 범위 밖: 수집·중복 제거·배포([docs/pipeline.md](pipeline.md)), 화면·타이포그래피
  ([docs/design-system.md](design-system.md)), 공개 정책 전문(`/standards`).
- 불변 원칙(요약): **AI 초안 + 사람 에디터 리뷰**, **no tracking**(분석·광고 스크립트 0),
  **no advice**(YMYL 배제), **draft → 사람 승인 게이트**.

### 1-1. 발행 언어

발행되는 필드 값(headline, body, whyItMatters 등)은 사이트 언어인 **영어**로 쓴다. 이 문서는 내부
운영 규칙이므로 한국어로 유지한다.

## 2. 제품 한눈에

| 항목 | 값 |
| --- | --- |
| 버티컬 | `ai`, `bio`, `geo`, `markets` (표시명: AI · Bio & health · Geopolitics & security · Markets & macro) |
| 주기 | 매일 07:00 KST (paseo schedule): collect → dedup → synth → validate → draft 커밋 |
| 발행 단위 | 날짜 × 버티컬 1파일 = 에디션. 홈(`/`)이 그날의 표지 |
| 작성 경로 | `scripts/synth.ts --input-json`(에이전트·에디터 작성) 또는 LLM 초안 + editor pass |
| 게이트 | `scripts/validate.ts` + AI editor pass(`scripts/prompts/editor.md`) + 사람 승인 |
| 독자 접점 | `/`, `/archive`, `/story/<slug>`, `/<vertical>`, `/rss.xml`, `/llms.txt` |

## 3. 버티컬 정의와 경계

| 버티컬 | 싣는 것 | 싣지 않는 것 |
| --- | --- | --- |
| **AI** | 모델·컴퓨트·정책·산업 경쟁, 인프라 투자, 규제 움직임 | 단순 제품 리뷰, 튜토리얼, 벤치마크 자랑 |
| **Bio & health** | 산업·투자 관점: 임상·승인·규제, 플랫폼 기술, 제약·바이오텍 딜과 자금 | 웰니스·라이프스타일, 일반 건강 정보·복용 지침, 개인 건강 조언 |
| **Geopolitics & security** | 권력·분쟁·동맹, 공급망·에너지 안보, 국정 운영과 제재 | 진영 논평, 전쟁 중계의 반복, 미확인 소문 |
| **Markets & macro** | 금리·물가·에너지·실적, 자금 흐름과 정책 변화 | 투자 권유·가격 목표·매매 신호, 시세 단순 중계 |

- **Bio & health는 웰니스 매체가 아니라 산업·투자 인텔리전스 버티컬이다.** 소비자 건강 콘텐츠는
  어떤 형태로도 넣지 않는다.
- 버티컬 귀속이 애매한 개발은 1차 영향이 가장 큰 버티컬에 배치하고, 다른 버티컬과의 연결은
  `whyItMatters`에서 다룬다(§5의 교차 리드 후보로도 검토).
- 포함 판단의 공통 조건은 `/standards` §7을 따른다: 문서화됨, 해당 분야 독자에게 중대함,
  전일 보도 반복이 아님.

## 4. 하루 에디션 구성과 쿼터

### 4-1. 하드 경계 (게이트)

- 에디션당 `stories`는 **1~8편**(`scripts/validate.ts`). 0편(빈 에디션 파일)과 9편 이상은 무효다.
- 버티컬당 클러스터 상한은 **8개**(`scripts/prompts/triage.md`).
- 이론적 하루 상한은 32편(4 × 8)이지만 이는 안전 상한이지 목표가 아니다.

### 4-2. 쿼터 유동화

- **버티컬별 균등 개수를 강제하지 않는다.** 그날의 신호 강도(클러스터 크기, 파급력)에 따라 무게를
  달리한다. 예: AI 5 : Bio 1 허용.
- 권장 밴드: **하루 전체 12~24편, 활성 버티컬당 3~6편.** 조용한 버티컬이 있으면 하한은 그만큼
  낮아진다. 실측 예: 2026-09-20 = 23편(AI 6 / Bio 6 / Geo 5 / Markets 6).
- 상한 8에 붙는 버티컬은 클러스터 품질을 재점검한다. 개수를 채우기 위해 노이즈·중복·저신뢰
  아이템을 넣지 않는다.
- 참고: 홈 인덱스 표시 상한은 14행(`HOME_INDEX_CAP`)이며 편집 쿼터가 아니다. 사이트 정렬은
  클러스터 수 → 읽기 시간 순(`bySignal()`)이므로, 중요도가 높은 스토리는 클러스터·깊이를 실제로
  확보해야 상단에 온다.

### 4-3. 조용한 버티컬

- 의미 있는 스토리가 없으면 그 버티컬은 **스킵할 수 있다.** 수집 결과가 비면 `synth.ts`가 해당
  버티컬 파일을 쓰지 않고 건너뛴다(수집 0건 시 `skipping`).
- **정직하게 표기한다.** 그날 편집 로그(커밋 메시지 또는 해당일 관련 `editorNote`)에
  `quiet: <vertical>` 한 줄을 남긴다. 사이트는 그날 해당 버티컬 스토리가 없으면 홈 버티컬 타일에
  "No stories on this date"를 자동 표시한다.
- 주의: 스키마에 quiet 필드가 없다. "오늘은 조용함"이라는 **문장을 사이트에 노출하려면** 스키마·UI
  변경이 필요하며 이 가이드 범위 밖이다. 현재는 로그·커밋으로만 기록한다.
- 모든 버티컬이 조용한 날은 에디션을 발행하지 않고 사유를 로그에 남긴다. 사이트는 직전 에디션을
  최신으로 유지한다.
- 금지: 조용한 버티컬을 메우기 위한 재탕·추측성·단일 출처 아이템 편입.

## 5. 오늘의 핵심 신호 (교차 리드)

- 하루 **1개**. 2개 이상 버티컬을 연결하는 교차 리드로, 그날 에디션의 대표 신호다.
- 선정 기준(모두 충족을 우선):
  1. **파급력** — 자금·정책·공급망·경쟁 구도에 미치는 영향의 크기.
  2. **교차성** — 연결되는 버티컬이 2개 이상이며, 연결이 주제 언급이 아니라 인과적이어야 한다
     (예: AI 규제 → 컴퓨트 조달 → 시장 수급).
  3. **신규성** — 전일 에디션 대비 새로운 정보·전환점. 반복 보도는 탈락(`/standards` §7).
- 절차: 그날 수집·클러스터에서 2개 이상 버티컬에 걸친 후보를 먼저 추린다 → 파급력으로 순위를
  정한다 → 동률이면 신규성으로 가른다. 선정된 스토리는 `whyItMatters`에서 연결 버티컬을 명시한다.
- 정합성 한계(중요): 현재 스키마·화면에는 `core signal` 같은 전용 필드·슬롯이 없다. 홈의
  "Start here"는 `bySignal()`(클러스터 수 → 읽기 시간) **자동 선정**이다. 따라서 이 절은 선정·프레이밍
  규칙이며, 선정된 교차 리드가 표지 1번에 오게 하려면 그 스토리의 클러스터·깊이를 실제로 가장
  강하게 만들거나(자동 정렬 활용), 향후 전용 슬롯 도입이 필요하다. 이 가이드는 코드·스키마 변경을
  요구하지 않는다.

## 6. 아이템(스토리) 형식

### 6-1. "무엇이 움직였나 / 왜 중요한가 / 출처" 매핑

| 질문 | 필드 |
| --- | --- |
| 무엇이 움직였나 | `headline`, `dek`, `tldr`, `body` (검증 가능한 사실) |
| 왜 중요한가 | `whyItMatters` (분석·함의, 교차 버티컬 연결 우선) |
| 출처 | `sources`(본문 인용) + `cluster`(같은 개발의 타 매체 링크) |
| 편집 판단 기록 | `editorNote`(수정·불확실성·출처 부족 사유) |

### 6-2. 필드 규칙

| 필드 | 필수 | 규칙 (게이트 포함) |
| --- | --- | --- |
| `slug` | O | kebab-case, 에디션 내 유일. 전역 중복은 사이트에서 경고 후 무시되므로 피한다 |
| `headline` | O | 비어 있으면 실패. 수치·고유명사는 원문 표기 그대로(verbatim), clickbait 금지 |
| `dek` | X | 한 줄 스탠드퍼스트 |
| `type` | O | `BRIEF`(단일 속보성 사실) / `DEEP`(다각도 전개) / `DATA`(숫자·데이터셋) |
| `readMinutes` | O | 1~60 |
| `tldr` | O | **정확히 3문장**, 각각 독립 |
| `body` | O | 1개 이상 블록. **블록마다 인용 ≥1**, 모든 인용 id는 `sources[]`로 해석되어야 함 |
| `whyItMatters` | O | 분석 1단락. 교차 버티컬 연결을 1순위로 |
| `editorNote` | O | 편집 근거·불확실성·수정 이력 |
| `cluster` | O | 같은 개발의 타 매체 링크 ≥1. 지지·보증이 아니라 비교용 |
| `sources` | O | 인용 목록. **distinct `source` 값 ≥2 (하드 게이트)**, `id` 중복 금지 |
| `tags` | X | 문자열 배열 |
| `confidence` | X | `high`/`medium`/`low`(기본 `medium`). 증거 수준이며 중요도가 아님 |

### 6-3. 출처 규칙

- **하드 게이트는 "서로 다른 `source` 값 2개 이상"**이다(`scripts/validate.ts`). 같은 개발에 대한
  독립 출처가 2개 미만이면 발행하지 않는다.
- 게이트와 표시의 차이를 이해한다: 게이트는 `source` 라벨 기준, 사이트가 보여주는 소스 수는
  hostname 기준(`editions.ts`의 `sourceCount()`)이다. 같은 도메인의 라벨만 다른 링크 2개는 게이트를
  통과해도 독립 출처 2개가 아니고 표시 소스 수도 1로 보일 수 있다. 서로 다른 매체·원문으로 확보한다.
- 원문 우선순위(`/standards` §2): 원문(제출서류·논문·성명·데이터셋) → 자체 취재 보도 → 2차 종합.
  2차 종합은 발견 용도로만 쓰고 주장의 근거로 인용하지 않는다.
- 보도자료·소셜 포스트가 기록의 출처일 때는 그 사실을 밝히고, 독립 확인으로 제시하지 않는다.
- 요약 발췌는 400자 상한을 넘기지 않는다. arXiv·PubMed·bioRxiv는 메타데이터만 쓰고 요약은 직접
  작성한다. GDELT 사용 시 "GDELT Project" 출처 표기를 유지한다.
- `confidence` rubric(`/standards` §3): high = 독립 primary 2개 이상 또는 반박 없는 단일 권위,
  medium = 단일 신뢰 출처 또는 개요는 일치하나 세부 불일치, low = 개발 중·논쟁 중·이력 미검증.

## 7. 톤과 문체

- 대상은 테크·비즈니스 전문가다. 배경 설명은 최소화하고, 판단에 필요한 맥락과 숫자는 충분히 준다.
- 금지: 과장, clickbait 헤드라인, 최상급 남용("역대급", "충격"), 이모지, 감탄사(!), 호명("여러분"),
  근거 없는 전망. 헤드라인 수치는 원문 그대로 쓴다.
- **no advice (YMYL)**: bio·markets에서 매수·매도·투자 권유, 가격 목표, 매매 신호, 복용·임상 지침을
  쓰지 않는다. 사실과 문서화된 범위만 서술하고 불확실성을 표기한다.
- `whyItMatters`는 사건 요약이 아니라 "왜 지금 중요한가"다. 교차 버티컬 연결을 우선하되 억지 연결은
  금지한다. 연결이 없으면 산업·정책적 함의로 쓴다.
- AI 초안 문구를 그대로 발행하지 않는다. 사람 에디터가 정확성·프레이밍·인용·톤을 검토·수정한
  문장만 발행된다(`/standards` §1).

## 8. 검증 게이트와 승인

흐름: synth draft → `validate.ts` → 자동 draft 커밋 → 사람 승인 → 발행.

| 게이트 | 강제 | 내용 |
| --- | --- | --- |
| `stories` 1~8 | `validate.ts` | 빈 에디션·9편 이상 실패 |
| distinct sources ≥2 | `validate.ts` | 스토리마다 서로 다른 `source` 값 2개 이상 |
| citation resolve | `validate.ts` | body 인용 id가 `sources[]`로 전부 해석 |
| `tldr` 3문장 | `validate.ts` | 정확히 3개 |
| `cluster` ≥1 | `validate.ts` | 빈 클러스터 실패 |
| headline·slug | `validate.ts` | headline 비어 있으면 실패, slug 형식·중복 검사 |
| enum·범위 | `validate.ts` | `vertical`/`type`/`confidence` enum, `readMinutes` 1~60 |
| AI editor pass | `scripts/prompts/editor.md` | 중복 병합, 미지원 주장 제거, 인용 무결성, YMYL 톤, `confidence` 확정 |
| 사람 승인 | 프로세스 | 자동 커밋은 draft. 사람 에디터 리뷰·수정이 승인 게이트 |

- 실행: `npx tsx scripts/validate.ts src/content/editions`(위반 시 exit ≠ 0), `npm test`(dedup +
  publish validation).
- 승인은 스키마의 `approved` 플래그가 아니라 **절차**다. 자동화는 draft만 커밋하고, 사람 에디터의
  검토가 끝난 뒤에만 발행으로 취급한다.
- 게이트 위반 아이템은 발행하지 않는다. 예외는 없다. 발행 후 오류는 `/standards` §5에 따라 해당
  아이템의 `editorNote`에 교정 이력을 남긴다.

## 9. 4~6주 버티컬 판정 계획

- 시점: 이 가이드 시행 후 **4~6주**.
- 판정 대상: 버티컬별 **유지/교체**.
- 판정 기준: **GSC 노출·클릭**, **독자 회신**.
- 측정 수단: **현재 없다.** 사이트는 no tracking 원칙에 따라 분석 스크립트를 쓰지 않고(README
  "Analytics: none by design"), GSC 연동과 독자 회신 수집 채널도 아직 없다. 따라서 지금 시점에는
  판정 데이터를 수집할 수 없다.
- 선행 조건: 판정 전에 (a) GSC 또는 동등한 검색 성과 데이터 연결, (b) 독자 회신 채널(메일 등)
  정의가 필요하다. no tracking 원칙을 깨는 도구는 배제한다.
- 수치 임계값은 측정 수단 확보 후에 정한다. 지금 확정하지 않는다.

## 10. 일일 편집 체크리스트

1. 버티컬별 신호 강도를 정렬하고 무게를 배분한다(하루 12~24편 밴드, 균등 강제 금지).
2. 조용한 버티컬은 스킵하고 `quiet: <vertical>` 한 줄을 로그에 남긴다. 억지 채우기 금지.
3. "오늘의 핵심 신호" 후보를 추린다(교차 ≥2 → 파급력 → 신규성).
4. 스토리별 필드를 점검한다: `tldr` 3문장, 인용 해석, distinct `source` ≥2, `cluster` ≥1,
   headline 수치 verbatim.
5. 톤을 점검한다: 과장·clickbait·이모지·감탄사 제거, YMYL no advice, 교차 연결 우선.
6. `validate.ts`를 통과시킨 뒤 AI editor pass를 거치고, 사람 에디터 리뷰·수정으로 승인한다.
