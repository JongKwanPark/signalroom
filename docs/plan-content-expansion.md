# 카테고리 확장 기획안과 작업 계획

이 문서는 카테고리 확장의 목적, 구현 계약, 작업 분담과 완료 기준을 소유한다. 발행 절차는 [수동 발행 런북](manual-publish.md), 편집 규칙은 [편집 가이드](editorial-guide.md), 화면 기준은 [디자인 시스템](design-system.md)을 따른다.

## 목적과 결정

운영자가 뉴스, 기사 기반 특집, 철학·고전 해설과 개인 에세이를 원하는 시점에 발행할 수 있도록 한다. 사이트 카테고리는 AI·BIO·GEO·MARKETS·WISDOM·SOCIETY의 여섯 개다. WISDOM은 철학·고전·삶의 성찰, SOCIETY는 사회·문화·교육·노동을 다룬다. 세부 주제와 철학자는 태그로 표현한다.

카테고리와 글 형식은 별개다. 어떤 카테고리든 수동 특집·분석·에세이를 지원한다. 기존 뉴스 묶음과 기사 기반 특집은 날짜별 에디션 형식을 사용한다. 자유로운 본문이 필요한 글은 독립 Markdown 글로 작성하며, 동일한 카테고리·검색·아카이브·RSS에서 발견할 수 있다.

정기 자동 발행은 현재 활성화된 Paseo 아침·저녁 스케줄을 기준으로 운영한다. 자동 수집 대상은 기존 네 분야로 유지한다. 새 카테고리는 수동 발행부터 시작한다. 사용자 요청에 따른 수동 발행은 기존 검증·빌드·커밋·push·Vercel 배포 절차를 따른다. 카테고리 확장은 코드·문서·검증을 대상으로 하며 새 글의 창작은 포함하지 않는다. 프로덕션 반영은 사용자의 배포 요청에 따라 진행한다.

## 데이터와 화면 계약

- 카테고리 목록과 자동 발행 대상은 순수 TypeScript 정의 한곳에서 관리한다. 웹의 여섯 카테고리가 자동 수집 스크립트의 `--vertical all` 대상을 늘리지 않는다.
- 기존 `editions` 컬렉션과 기사 URL을 유지한다. 독립 `articles` 컬렉션을 추가하며 공개 URL은 `/{lang}/story/{slug}`다.
- 에디션 스토리는 선택적 `publication: 'scheduled' | 'manual'`로 발행 경로를 표시한다. 기본값은 `scheduled`다. 히스토리로 확인된 기존 특집은 `manual`로 표시하며, 본문은 변경하지 않는다. 독립 글은 수동 발행으로 취급한다.
- 독립 글의 메타데이터: `slug`, `title`, `description`, `category`, `format` (`essay`·`feature`·`analysis`), `author`, `lang`, `publishedAt`, 선택적 `updatedAt`·`translationKey`, `tags`, `draft`, 선택적 `sources`. 본문은 Markdown이다. `draft` 기본값은 `true`이며 공개 경로는 `draft: false`인 글만 취급한다.
- 독립 글은 원문 언어로 발행할 수 있다. 번역본은 같은 `translationKey`로 연결하고, 번역이 없으면 상대 언어 홈으로 안내한다. 기존 에디션의 번역 규약은 유지한다.
- 공통 조회는 기존 기사 속성을 유지하며 `kind: 'edition' | 'article'`로 구별한다. 독립 글은 `articleId`, `format`, `author`, 발행·수정 시각을 제공한다. `getEditions()`와 `allStoryRefs(editions)`는 에디션 전용, `getStoryRefs(lang)`는 공개된 두 컬렉션의 통합 조회다.
- 뉴스에 대한 기존 출처 검증은 유지한다. 독립 글은 고전의 직접 인용·사실·역사적 설명에 출처를 제시하고, 개인 경험과 해석을 저자 글로 표시한다. 뉴스용 관련 보도 수·신뢰도는 독립 에세이 화면에 강제하지 않는다.
- 홈은 정기 뉴스 날짜와 별도로 최근 수동 글을 표시한다. 카테고리 카드에는 해당 분야의 최신 글을 표시한다. 글이 없는 새 분야는 설명과 빈 상태로 안내한다.
- WISDOM은 태그로 철학자·주제를 탐색한다. 카테고리 메뉴는 모바일·키보드에서도 사용할 수 있다. 현행 타이포그래피와 다크·라이트 테마를 확장한다.
- 검색·RSS·일반 사이트맵은 공개된 독립 글을 포함한다. 뉴스 사이트맵은 뉴스 기사만 포함한다. 초안은 모든 공개 출력에서 제외한다.

## 병렬 작업 계획

| 레인 | 담당 범위 | 의존성 |
| --- | --- | --- |
| 데이터 | 공통 카테고리, Astro 컬렉션·통합 조회, 검색·SEO 데이터, 검증기와 관련 테스트 | 위 데이터 계약 |
| 화면 | 홈·카테고리·글·아카이브·메뉴·피드·테마, Markdown 렌더링 | 데이터 레인의 공통 조회 계약 |
| 문서 | 실제 자동·수동 운영에 맞춘 기존 문서·발행 스킬 정리 | 위 결정과 구현 계약 |
| 통합 | 자동 수집 대상 보존, 공유 이미지·빌드 설정 연결, 통합 검증 | 데이터·화면 완료 |

각 레인은 같은 작업 트리에서 겹치지 않는 파일만 수정한다. 의존성이 있는 부분은 인터페이스를 먼저 공유한다. 서브에이전트는 재위임하지 않으며, 결과는 변경 경로·요약·검증 결과·남은 문제로 보고한다.

## 완료 기준과 검증

1. 한·영 WISDOM·SOCIETY 경로와 여섯 카테고리 탐색이 생성된다.
2. 기존 기사와 수동 특집이 정상 렌더링되고, 자동 발행 대상과 스케줄 설정은 유지된다.
3. 독립 Markdown 글이 카테고리·검색·아카이브·RSS·사이트맵·공유 이미지에 연결된다. 실제 발행용 예시 글은 만들지 않고, 검증용 픽스처로 발행·초안·번역 연결을 확인한다.
4. 에세이에는 뉴스용 필수 관련 보도·단락별 인용·3개 요약을 강제하지 않는다. 초안·중복 slug·잘못된 메타데이터는 공개되지 않는다.
5. 문서는 자동 배포까지 수행하는 실제 운영과 수동 발행을 설명하고, 소유 문서로 연결한다.
6. 관련 최소 테스트, Astro 타입 검사, 사이트 빌드가 통과한다. 브라우저 검증은 로컬 산출물을 대상으로 수행한다.

참조 표준: WCAG 2.2 AA, strict TypeScript, Diátaxis.
